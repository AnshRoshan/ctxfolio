# `ctx` CLI reference

Zero-dependency Node 22/24 script. Lives in the skill at `scripts/ctx.mjs`; `setup`/`init` copy it to `context/ctx.mjs` so the wiki is self-contained and portable. **After setup, always run from the project root with relative paths** — `node context/ctx.mjs <command>` (root is auto-detected; `--root <dir>` only for operating on another project). Git is used for staleness/impact; without git those features say so and skip.

```
node context/ctx.mjs <command> [args]
```

Commands with `[--json]` emit one object: `{ command, ok, … }`; misuse emits `{ command, ok: false, error, exitCode: 1 }` and exits 1. `ok` is a health signal, not a correctness guarantee. `brief` stays exit 0 for a valid query even if `ok: false`; consumers must inspect the payload.

Additional commands: [scaffold/hosts/check/symbols/search/MCP/teams](scale-and-hosts.md), [actual cold-start evidence](cold-start-evidence.md). `eval` runs the frozen routing fixture; `evalpack` prepares but does not perform an experiment. `capture digest` is read-only unless `--write`; approval and promotion are separate explicit operations.

## Resume-cursor advisories

`status`, `brief` and SessionStart expose a read-only `resumeCursor` observation. It compares repository HEAD with the last committed memory.md update and reliable project-scoped Git status; it never rewrites memory or changes Stop/health/exit semantics. HEAD is repository-global, so unrelated sibling commits can produce a qualified lag warning.

Local cursor edits are not freshness evidence. Missing/untracked/unsafe cursors or unavailable/limited history/status remain unknown; no warning or lack of warning means verified. Only standalone `Working tree: nothing pending.` or legacy `Nothing pending.` in Current state is a Git-clean claim. Quotations, code examples, history and incidental prose are excluded. A pending claim means tracked/nonignored-untracked project changes, not task completion. Reconcile recorded next steps with their task/spec owners when warned.

## Native symlink setup

Fresh projects default to `resourceMode: symlink`. Existing configs without a mode retain the legacy pointer strategy until explicit `ctx symlinks --migrate` or `setup --symlinks --migrate`; `--portable-pointers` is a deliberate opt-out. Unsupported native permission fails before fresh owner pages are created and never silently creates regular aliases. A failed later installation does not falsely commit native mode; its pending request is retained and retries remain native. Installed/pending native layouts reject `--portable-pointers` until a deliberate reviewed reverse migration exists.

On Windows, tell the human to enable Developer Mode or obtain the create-symbolic-link privilege. `Start-Process 'ms-settings:developers'` opens Settings; the skill does not toggle OS security. After verified creation, existing aliases, checks and normal canonical edits work with creation permission disabled. Git clones/checkouts and missing-link repairs may require it again. For a repository that already contains links, clone with `git -c core.symlinks=true clone <repo>` while the OS permission is available; setting the option afterward does not automatically convert fake checkout files.

Git is configured with `--local core.symlinks true`, never global. Native types/relative targets are checked with lstat/readlink; a regular file containing a link target is not a symlink. Junctions/absolute targets are not substituted. Claude-only notes must be deliberately moved out of CLAUDE.md before it becomes the shared alias. Migration stages all links before replacing old generated wrappers and preserves recovery backups if rollback cannot finish.

Compatible host resource folders share .agents directly. Cursor metadata lives once under `.agents/views/cursor/rules`; its body resolves `ctx_source` from the project root, avoiding alias-depth-dependent Markdown paths.

## Canonical resources and legacy portable links

- `.agents/agents/<name>.md`, `.agents/rules/<name>.md` and `.agents/skills/<name>/SKILL.md` own reusable instruction bodies. `context/ownership.md` owns the file-responsibility contract; native tools never maintain a second body.
- Native adapters declare `ctx_source` and discovery metadata plus a relative Markdown link. Metadata is a generated view; after editing a canonical description/glob/tool list, run `ctx adapters`, then `ctx adapters --check`.
- Checksums detect edits to generated adapters; refresh refuses to overwrite hand changes. Do not edit generated views as an alternative to their source. Only compatible resource directories are linked; whole native settings folders are never aliased.
- `ctx adapters --migrate` is explicit adoption: promote a sole unmanaged native resource into an absent canonical location, preserving its text, then replace the native body with an adapter. Competing canonical/native bodies require manual resolution; no silent merge. Legacy skill folders with companion assets require a deliberate folder migration, not a SKILL-only copy.
- Canonical roles are tool-neutral readable briefs, not a promise that every host automatically loads them. Claude native roles and Claude/Cursor rules/skills have adapters; Codex can use the shared skill tree. Verify actual loading inside each host.
- Lint/doctor detect missing core owners, unresolved/changed adapters and likely exact long live-prose duplicates. This cannot prove differently worded facts never drift; follow the ownership contract and review semantic overlap.

## Budgeted routing JSON

`brief --json` returns `alwaysRead` (page, tokens, missing), `pages` (page, title, type, status, summary, score, reasons, tokens, tldr, confidence, stale, changedSources, verificationRequired, warnings), `skipped` (page, tokens, reason: budget|limit), `blindSpots`, `estimatedTokens`, `budget`, `budgetExceeded`, and `gitAvailable`.

- Estimates are full-page characters / 4, not exact model token counts; they exclude AGENTS.md, chat, code reads and CLI output. `--limit` is a positive integer; `--budget` a non-negative integer. No budget means `budget: null`.
- Mandatory `alwaysRead` files must be project-relative, non-secret regular files within the real project boundary; entries are deduplicated and never silently dropped. Known module pages get the same trust warnings as task results; retired mandatory pages are rejected unless `--history`. If they exceed the budget, report `budgetExceeded: true` and select no task pages. Otherwise `estimatedTokens <= budget`; a large top result is skipped so a smaller result can fit.
- `verificationRequired` flags stale, retired, unfilled, inferred/unverified or missing-confidence code claims, and covered working-tree changes (`changedSources`), including when git is unavailable. These are structural/freshness signals, not an evidence parser: inspect the body's source/check evidence even when the flag is false. A stamp, touched page or clean git report cannot prove semantic correctness.
- `ok: false` means overflow, missing/untrusted mandatory orientation, no selected pages, a blind spot, or a selected page needing verification. Inspect the reasons; do not interpret it as permission to skip source checks.
- `--history` includes retired pages still in the searchable wiki; it does not search excluded `context/archive/` files. Historical text is evidence, not current instructions.

## Config — `context/.ctx.json`
Generated by `init`/`setup` from the detected profile (`sourceExt` and `ignoreSourceGlobs` speak the project's language). Keys: `resourceMode` (installed `pointer` or `symlink` strategy), transient `requestedResourceMode` (retains an uncompleted native request), `setupVersion`, `profile`, `maxPageLines`, `maxAgentsLines`, `maxSummaryChars`, `alwaysRead`, `archiveAfterDays`, `trackerKeepDays`, `sourceExt`, `ignoreSourceGlobs`, `ignoreDirs`, `pageExcludes`. Anything omitted keeps its default.

## Lint rules (what it checks)
Errors: missing frontmatter or required field · broken relative link or `[[wikilink]]` · missing `index.md`/`AGENTS.md` · duplicate decision IDs · feature in two tracker states · Feature id listed twice in one tracker section (branch-merge collision) · tracked unit with no spec (In progress/Completed) · decision record missing a required field (Trigger/Options/Chosen/Lost alternative/Cost/Reversibility/Correctness policy) · spec `complete` with unticked checks · missing core ownership/resource files · unresolved/stale/conflicting native adapters · secret-looking strings · (strict) unfilled `{{placeholders}}`.
Warnings: probable exact duplicate live prose (long paragraphs; pointers, templates and dated snapshots excluded) · stale pages · orphans not in the index · dead `covers` globs · page > limit lines · no TL;DR on 40+ line pages · summary too long · superseded without `superseded_by` · unknown status · references to nonexistent D-NN · more than one unit In progress · tracked unit with no spec (Up next/Blocked) · two specs sharing a number (merge collision) · machine-specific absolute path in a page · AGENTS.md too long / not routed through the index · CLAUDE.md not importing AGENTS.md · legacy instruction files.

## Wire-up checklist
1. `settings.json` hooks → `SessionStart` + `Stop` (template included).
2. Optional `.git/hooks/pre-commit` from `assets/pre-commit.template`.
3. CI step: `node context/ctx.mjs lint` (add `--strict` later).
4. Verify like code: change a covered file and confirm the Stop hook blocks; run with `stop_hook_active: true` and confirm it doesn't loop.
